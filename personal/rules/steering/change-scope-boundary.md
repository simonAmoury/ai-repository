# 变更影响边界规则

## 只删改本次任务自己产出的文件

- 清理 / 回收 / 删除操作，只针对**本次任务自己新建**的文件与代码。仓库中原有的文件一律不得删除或改写，哪怕它看起来像临时产物（如名为 `Test.java`、`tmp_*`、`demo`、内容是一段 main 方法或被注释掉的代码）。
- 判断「是否本次产出」不能靠文件名像不像临时文件、也不能靠印象，必须先核实：用 `git status` / `git log` 确认它是本次新增的 untracked 文件，还是仓库既有的已跟踪文件。**只要 HEAD 中已存在，就是既有文件，不属于本次清理范围。**
- 用户说「把 X 去掉」「清理掉 X」时，作用域默认限定为**本次任务范围内的 X**，不扩大到仓库里所有同类文件。范围有歧义时先问清楚，不要自行扩大解释。
- 误删既有文件后，立即用 `git show HEAD:<path>` 取原内容原样恢复，并说明原因；**不要凭记忆重写**内容。

## 收尾清理的安全做法

- 执行批量删除前，先列出待删清单；在汇报中逐条说明「删了什么、依据什么判定它属于本次产出」。
- `git status` 里 `modified` 的既有文件，只保留本次任务必需的改动，其余顺手改动一律复原。
- 临时探测脚本、为跑测试临时改的构建配置，只回收自己加的那部分，不动他人既有配置。
